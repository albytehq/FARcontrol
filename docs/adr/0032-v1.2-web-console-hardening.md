# ADR-0032 — v1.2.0: Web console v1.2 (session-first IA) + localhost hardening

- Status: ACCEPTED (owner instruction 2026-10-03: master prompt §9–§10, §28,
  §32; approved via "lanjut ke ADR dan jalankan mission project 1.2.0")
- Date: 2026-10-03
- Research: docs/research/r10-console-session-ia.md, r11-realtime-sse-polling.md,
  r12-localhost-security-ux.md, r13-session-time-ux.md, r15-terminal-a11y-compat.md
- Depends on: ADR-0028 (session model), ADR-0030 (agent heartbeats)

## Context

v1.1's console v2 is device-registry-centric (r10 finding: it reads like a
device management dashboard for a product that now has exactly one device).
The master prompt §32 wants the console to answer **THIS IS THE CURRENT
SESSION**: device id, session state, agent connection state, active
operations, security/audit info. Research also found two concrete defects: a
WCAG AA contrast failure (nav badge `#4F8CFF` on `#1D3153` = 4.04:1, needs
≥4.5:1 at 11 px — computed, r15) and a missing Host-header allowlist on the
admin plane (DNS-rebinding class, r12).

## Designs considered

1. **SSE event stream** for live updates (r11's headline option). Rejected for
   v1.2: the console is single-user over loopback; a 3 s REST poll is
   indistinguishable in practice and avoids a second transport, connection
   management, and fallback paths (Rule 1). SSE stays a documented option for a
   future multi-user console.
2. **Session-first re-layout on the existing single-file console** (chosen):
   keep the zero-dependency, textContent-only, no-CDN security model
   (ADR-0017/0027) and reorganize what it shows.

## Decision

1. **Session header** (always visible): Device ID, daemon version, session age
   (started-at, r13 coloring: amber >1 h, red >4 h is a hint not an alarm),
   live **agent chips** (name + last-seen, fed by ADR-0030 heartbeats, aria-live),
   and the **PANIC** button persistent in the header.
2. **Tabs**: Activity (pending requests, sessions, approve/deny/revoke — the
   existing core), Audit (recent events, existing), Advanced (fingerprint,
   rotate, stop). The v1.1 Devices panel is removed (registry gone) — agent
   visibility lives in the header chips + `frtrol status`.
3. **Login label** says where the token comes from: "Admin token — printed by
   `frtrol start`" (r12: the token is now per-session, so the hint matters).
4. **Host-header allowlist** on the admin plane (middleware): `Host` must be
   `127.0.0.1[:port]`, `localhost[:port]`, or `[::1][:port]` → else 403
   `bad_host`. Kills DNS-rebinding against the cookie path. The agent plane is
   unaffected (HMAC, no ambient cookies).
5. **A11y fixes** (r15, computed): badge text `#4F8CFF` → `#CFE0FF` (7.6:1 on
   `#1D3153`), `:focus-visible` outlines, `aria-label`s on icon-only buttons,
   disable action buttons while a request is in flight (no double-approve),
   NO_COLOR-safe palette (contrast is computed on colors, independent of
   terminal).
6. Polling: `/ui/state` every 3 s while the tab is visible (`visibilitychange`
   pauses it — no background traffic, prompt §44).

## Consequences

- e2e gains: Host allowlist probe (curl with `Host: evil.example` → 403), and
  the existing UI flows keep passing (state layer functions unchanged).
- The console stays one embedded HTML file with zero new dependencies.
- Mutation check: removing the Host check must turn the allowlist e2e red.
