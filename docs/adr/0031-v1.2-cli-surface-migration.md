# ADR-0031 — v1.2.0: CLI surface redesign + v1.1 migration

- Status: ACCEPTED (owner instruction 2026-10-03: master prompt §7–§8, §30, §33–§34;
  approved via "lanjut ke ADR dan jalankan mission project 1.2.0")
- Date: 2026-10-03
- Research: docs/research/r6-start-panel-cli-ux.md, r14-agent-machine-ux.md,
  r9-error-ux-taxonomy.md
- Depends on: ADR-0028, ADR-0029, ADR-0030

## Context

The whole CLI must read as one product (master prompt §30: "avoid having ten
commands designed by ten different people"). v1.1's surface still tells the
v1.0/1.1 story (`device add`, `agent login`, permanent admin token). v1.2's
story is: `start` mints the session → `agent` connects → `request/approve` →
capabilities → session end.

## Designs considered

1. **Keep the v1.1 commands as aliases on top of the new model.** Rejected:
   `device add` literally cannot work (there is one machine device, minted by
   `start`); keeping dead commands is the dead-code smell (discipline Rule 1)
   and confuses the two-factor story the owner explicitly replaced.
2. **Clean break with a migration path** (chosen): remove what contradicts the
   new model, keep everything that still tells the truth, document every
   removal in the CHANGELOG (master prompt §33–§34 allow breaking changes when
   documented).

## Decision — owner side

| Command | v1.2 |
|---|---|
| `frtrol start` | mints + prints the session box (r6: Device ID, Session Password, Web UI URL, Admin Token, agent line, "credentials die with this process"); `--verbose` for operator detail (binds/fingerprint/policy) |
| `frtrol stop` | **new** — graceful shutdown via admin plane (`POST /v1/admin/shutdown`) |
| `frtrol status` | shows the session: device id, uptime, live agents (from heartbeats), pending/active counts; `--json` additive schema |
| `frtrol list` | unchanged table minus the DEVICE column (single device now) |
| `frtrol approve/deny/revoke/audit/panic/doctor/backup/restore/init` | unchanged |
| `frtrol rotate` | re-mints Session Password + Admin Token mid-run (shows new password once) |
| `frtrol fingerprint` | unchanged (TOFU out-of-band compare) |
| `frtrol device …` | **removed** (registry gone, ADR-0028) |
| bare `frtrol` | quick guide rewritten for the v1.2 flow |

## Decision — agent side

| Command | v1.2 |
|---|---|
| `frtrol agent` | **new** interactive connect (ADR-0029): prompts → login → saves connection.json → spawns agentd → receipt |
| `frtrol agent status [--json]` | **new** — runtime state: connected/reconnecting/expired/revoked/stopped + last error |
| `frtrol agent stop` | **new** — clean runtime shutdown, credentials cleared |
| `frtrol agent ping/request/status/exec/read/write/ls/ps/kill/app/shot/type/revoke/term` | unchanged syntax; credentials now come from `connection.json` in the **agent home** (`~/.farcontrol-agent`) |
| `frtrol agent login` | **removed** (bare `frtrol agent` replaces it) |
| `--token` legacy flag | **removed** (v1.0 token flow retired, see migration) |

New admin-plane endpoints: `/v1/admin/status` (session + agents),
`/v1/admin/shutdown`. Removed: `/v1/admin/devices/*`. Every new command keeps
the r14 contract: flags + env twins + `--json` + §66 exit codes + one-line
receipts; errors follow r9 (`✗ what — hint`, next command shown).

## Migration (one-time, migration v5, runs at `frtrol start`)

1. Existing v1.1 device rows → `locked`, login disabled, keys rotated to noise,
   their active grants revoked, audit `device.model_migrated` (v1.1 agents must
   reconnect with the new session password — same handover UX they already had).
2. v1.0 legacy token device → same treatment; the token auth path is removed
   (`agent_token` meta ignored).
3. Machine device row created (or reused) with the stable device id; fresh
   session password + key minted (ADR-0028).
4. Old `device-id`/`device-key`/`agent-token` files in an owner data dir are
   never read by v1.2 agent commands (agent home is separate).

## Consequences

- Breaking: v1.1 `device` CLI, v1.0 token auth, `agent login` subcommand.
  Documented here + CHANGELOG; e2e gains a migration section that builds a
  v1.1-shaped DB and proves old credentials die.
- `frtrol start` while already running still fails on bind — now with a
  "already running: frtrol status / frtrol stop" hint (single session per
  device, master prompt §41).
