# ADR-0000 — Scope & Model Rilis v0.1.0

**Status:** ACCEPTED (by owner, 2026-10-02)
**Related:** spec §1–§10 (misi), docs/03-build-plan.md Phase 0–2, AGENTS.md (3 aturan mutlak)

## 1. Context
FARcontrol 0.1.0 harus membuktikan proposisi inti: AI agent eksternal dapat mengoperasikan komputer owner **tanpa akses permanen** — setiap akses lahir dari persetujuan eksplisit dan mati otomatis (grants 5h–72h). Aturan owner #1 melarang over-engineering; aturan #2 mensyaratkan "selesai = terverifikasi". Build plan menuntut walking skeleton duluan: `frtrol start` → request → ACCEPT/DENY, lalu memperdalam vertikal.

Binding (spec): authentication ≠ authorization; tidak ada akses tanpa approval aktif; semua security action tercatat audit. Recommended: walking skeleton sebelum fitur lengkap.

## 2. Known / Inferred / Unknown
- KNOWN: spec 108 requirement; tidak semuanya wajib di walking skeleton (docs/03 Phase 0–2).
- KNOWN: owner menjawab semua pertanyaan blocking (tracking/QUESTIONS.md) — Gate 0 terpenuhi.
- INFERRED: scope v0.1.0 = siklus hidup session penuh (request→approve/deny→exec→revoke→expire) + audit + policy standart, pada Linux. Ekstra (mTLS, multi-OS, web console) defer ke v0.2+.
- UNKNOWN: tidak ada yang menghalangi kode — owner sudah menyatakan "langsung buat".

## 3. Options
| Option | Isi | Risiko | Kompleksitas |
|---|---|---|---|
| A | Walking skeleton murni (request + ACCEPT/DENY saja, tanpa exec) | Tidak membuktikan value nyata; verifikasi tipis | Rendah |
| B | **Vertical slice penuh: session lifecycle + exec + file ops + audit + policy** | Scope lebih besar, tapi tetap <3k baris | Sedang |
| C | Semua 108 requirement sekaligus | Melanggar aturan owner #1 (over-engineering) | Tinggi |

## 4. Recommendation
**Option B.** Menjalankan siklus hidup penuh satu vertikal = bukti terkuat per unit usaha; eksekusi perintah nyata adalah inti produk. Semua yang bukan vertikal inti (mTLS, GUI, multi-OS, rate-limit mewah) dieksplisitkan sebagai deferred.

## 5. Security analysis
Trust boundary utama yang diuji: agent (B) → daemon. Invarian yang harus terbukti di v0.1.0: (1) no approval = no access, (2) expired = no access, (3) revoked = no access, (8) security action = auditable. Fail-closed: daemon mati = semua akses mati.

## 6. How we will verify it
e2e test (scripts/e2e.sh) menuntaskan: init → start → request → deny → request → approve → exec → scope-denied → revoke → expired → audit terisi. Ditambah unit test per modul (crypto, policy, state, exec, files, auth). Evidence: tracking/EVIDENCE-001.md.

## 7. Consequences
Lebih mudah: keputusan berikutnya (ADR-0001..0012) punya target konkret. Lebih sulit: tidak ada ruang fitur dekoratif. Deferred: mTLS, web console, macOS/Windows, streaming output, multi-agent registry.
